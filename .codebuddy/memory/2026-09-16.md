# 2026-09-16 第二轮：CRC 校验解决 + NONE 解修复 + 枚举差异 + 字体核查

## 1. CRC 校验算法（已彻底解决，不再是 unverified）
- **结论：两产品 `#` 类报文均为 32 位块 CRC-32（NovAtel 风格），不是 CRC-16。**
  - 算法依据：北云 UG016 表 4-6（p71），多项式 0xEDB88320，**初值 0x00000000**（区别于标准 CRC-32/PKZIP init=0xFFFFFFFF——这是此前全不匹配扫描不中的根因）。华测 M7 手册同样写 32-bit CRC。
  - 计算域：`#` 之后、`*` 之前的全部字符（不含 `#` 与 `*CRC`）。
  - 全量验证：两产品全部 `#` 类报文（北云 BESTGNSSPOSA/INSPVAXA/HEADINGA/TRACKSTATA；华测 BESTPOSA/BESTPA/BESTDOPSA/BESTVA/ENVSTATUSA/RANGEA/RTKPA/RTKVA/SATVIS2A）100% 匹配、0 错误。
- 代码：新增 `_crc32_block()`（按手册 C 代码，含 256 表缓存）；重写 `check_message_integrity()`：NMEA(\$) 做 XOR、`#` 类做 CRC32，均判 valid/invalid，返回细分统计 `nmea_*` 与 `hash_*`。报告 HTML/MD 从「未校验-算法待确认」改为分类显示通过率。

## 2. 北云 NONE 解遗漏（已修复）
- **根因**：`parse_bestgnsspos` 解析时坐标校验失败即 `continue` 丢弃，导致无有效坐标的 NONE 历元（北云 198 条、华测 7 条）被漏；卫星数 num_svs<1 也丢弃 NONE。
