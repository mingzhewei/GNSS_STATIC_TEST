## 一、全面审计结论（手册逐字段核对，零猜测）

### 1. 主位置字段映射——两解析器均正确
| 产品 | 主数据源 | 手册依据 | 结论 |
|---|---|---|---|
| 北云 | `BESTGNSSPOSA` | UG016 §4.2.2 BESTGNSSPOS | 映射正确 |
| 华测 | `BESTPA`（10 Hz，BESTPOSA 仅 1 Hz 兜底） | M7 V2.7 表3-38 BESTP | 映射正确 |

- 北云 payload：`sol_status, pos_type, lat, lon, hgt, undulation, datum, lat/lon/hgt σ, ...`；Field15-18 顺序 `#SVs, #solnSVs, #solnL1SVs, #solnMultiSVs`。
- 华测 BESTPA payload：`sol_status, pos_type, datum, reserved, lat, lon, hgt, undulation, lat/lon/hgt σ, diff_age, sol_age, #SVs, #solnSVs, #solnMultiSVs, #solnL1SVs`——**Multi/L1 顺序与北云相反，代码未互换，正确**。
- 华测 `#BESTPA` 头部 TOW 为毫秒，代码已除以 1000 统一为秒。

### 2. 已修复的 6 类问题
1. **undulation 语义标错（高）**：原写"天线高度/大地水准面高"。按两份手册，undulation=**高程异常（geoid undulation）**，非天线高。已统一显示为"高程异常 (geoid undulation)"（commit `e85dd63`）。
2. **CEP95 名称不准确（中）**：算法实际是"相对均值位置的水平径向误差 95% 分位数"，更准确的名称是 **R95 / 95% horizontal radial error**。算法不变，两代码+图例+报告全部改名 R95（commit `46e5042`）。
3. **华测 DOP 阈值与北云不一致（中）**：华测原 PDOP<3.0/HDOP<2.0，北云 PDOP<2.0/HDOP<1.5。已统一为 PDOP<2.0、HDOP<1.5。
4. **华测报告标题写错主数据源（中）**：原章节标题写 BESTGNSSPOSA，改为 `GNSS定位分析 (BESTPA)`；饼图标题改为 Position Source。
5. **北云报告结论 R95 硬编码 3.6 cm（中）**：改为动态读取 `pos_stats['r95']`。
6. **"行业标准"表述依据不足（中）**：95% 固定率、2cm R95、PDOP/HDOP、C/N0 分级未绑定具体标准条款，全部改为"工程阈值/工程经验分级"（commit `facb213`）。

### 3. 图片名与顺序——两产品共同部分一致
`pos_timeseries → en_scatter → position_sigma_ts → pseudorange_residual_ts → solution_type_pie → dop_timeseries → dop_histogram → skyplot → snr_distribution → satellites_used_ts → satellite_table → fix_rate_gauge → data_gap_analysis → performance_summary`（北云另有 INS 专属图，不视为不一致）。

### 4. 单位/口径——已统一
TOW=秒；位置/σ/伪距残差RMS/R95/2DRMS=m；速度=m/s；姿态=deg；DOP=无量纲；SNR·C/N0=dBHz；固定率=%。

### 5. 保留的差异（需用户确认后才统一，未擅改）
- **数据间隙口径不同**：北云用 BESTGNSSPOSA 0.2 s、阈值 5×（>1 s）；华测用 GGA 1 s、阈值 2×（>2 s）。属主数据流差异非映射错误。0920 数据按"各自主位置流 + 2×"检查两边间隙均为 0。

### 6. 0920 静态半边天数据复算基准
- 北云：4406/4406 固定解，R95=0.0303157 m，2DRMS=0.0344297 m，21 图。
- 华测：8772/8772 固定解，R95=0.0252649 m，2DRMS=0.0310276 m，14 图。

## 四、EXE 打包（`Build/`，commit `8acd9e7`）
- 工具：PyInstaller 6.20.0（Python 3.13.12，Windows 11 64-bit）。
- 内容：`GNSS_Static_HMI.exe`(1.96 MB) + `_internal/`（Python/Tk 运行时）+ `gnss_static_hmi.py` + `gps_rtk_analyzer_bynav.py` + `gps_rtk_analyzer_huace.py`；总计约 **23.7 MB**。
- **体积控制决策**：EXE 只打包 HMI（标准库+Tkinter），排除 numpy/matplotlib/scipy/pandas/PIL/pytest；分析器以源码脚本随附、由系统 Python 调用（与原有运行方式一致）。若把 numpy/matplotlib 打进 EXE 体积会超 100 MB。
- **路径适配**：`gnss_static_hmi.py` 新增 `ANALYZER_DIR = BASE_DIR.parent if ... else BASE_DIR`——Build 内的 HMI 能找到仓库根目录的分析脚本，也兼容平铺拷贝。
- **环境前提（已明确告知用户）**：EXE 在任何 Windows 上双击可开界面（自带运行时）；但点"分析"需系统 Python + numpy + matplotlib。完全免 Python 的版本（约 100–150 MB）待用户确认后再打。
- 验证：EXE 进程可正常拉起并安全关闭；Build 内 HMI 路径解析正确；两分析脚本经 HMI 方式实跑通过；临时构建目录（build_temp、GNSS_Static_HMI/）已清理。
