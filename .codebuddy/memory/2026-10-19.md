## 本轮目标
在既有北云 / 华测 GNSS 静态分析项目中新增加和芯星通 UM980（Unicore N4 / NebulasIV）模组测试，不修改既有北云与华测逻辑；完成手册逐字段核对、实测数据验证、统一 HMI 注册、双文件回归测试，并同步 GitHub。

## 数据与依据
- 数据：`beidou_data/1019beidou.log`（33s，8459 帧）、`beidou_data/1019beidou2.log`（53s，12939 帧）。
- 手册：`beidou_manual/Unicore Reference Commands Manual For N4 High Precision Products_V2_CH_R1.15.pdf`。
- 本轮实际核对的关键表：
  - 表 7-50/7-51：Unicore 二进制 / ASCII 消息头。二进制同步字 `AA 44 B5`，头 24B；`MessageID@4`，`MessageLength@6`，`Wn@10`，`Ms@12`。
  - 表 7-70：BESTNAV 数据结构（ASCII 输出为 `BESTNAVA`）。字段：p-sol status、pos type、lat、lon、hgt、undulation、datum id、lat σ、lon σ、hgt σ、stn id、diff_age、sol_age、#SVs、#solnSVs 等。
  - 表 7-137：OBSVM 数据结构，`Message ID 12`，`obs Number` 后每条 40B。
  - 表 7-138：Unicore PRN 范围。
  - 表 7-140：通道跟踪状态。bit10=载波相位有效，bit12=伪距有效，bit16-18=卫星系统，bit21-25=信号类型（5 bit）。
  - 表 7-174~7-177：SATSINFO 数据结构与系统/频点标识。
  - 表 7-76~7-80：BESTSAT 数据结构与信号掩码。
  - 表 7-169：RTKSTATUS 数据结构。
- 指令对照：`beidou_manual/UM980_北云指令对照表.md`。其中观测类消息供应商实测最高 1Hz。

## 与北云 / 华测的口径对照
1. **主位置流**
   - 北云：`BESTGNSSPOSA`。
   - 华测：`BESTPA`（10Hz；`BESTPOSA` 兜底）。
   - 北斗：`BESTNAVA`。本数据集实测 1Hz（34 条覆盖 33s；第二文件 54 条覆盖 53s）。
2. **固定解判定**
   - 三者统一使用 `SOL_COMPUTED` + `NARROW_INT/WIDE_INT/L1_INT` 等 RTK fixed 集合。
3. **静态精度算法**
   - 复用与北云/华测相同的 `llh_to_enu`、`calc_r95`、`calc_2drms`、固定解过滤、均值基准 ENU、标准差/RMS/峰值统计。
4. **数据完整性**
   - 已改为按主位置流 `BESTNAVA` 统计，不再用 GGA 替代；采样间隔按帧间隔中位数自适应。
5. **数据间隙**
   - 使用 `BESTNAVA` 主流时间轴；本数据集 0 间隙。
6. **单位**
   - 位置 / σ / R95 / 2DRMS：m；速度：m/s；DOP：无量纲；C/N0：dB-Hz；固定率：%；locktime：s。
7. **无时间戳消息**
   - GSA/GRS/GSV 周期与均匀性按 N/A 处理，不用 GGA 时间轴伪造。
8. **报告章节**
   - 1 数据概览；2 GNSS 定位分析；3 DOP；4 卫星可见性；5 原始观测与跟踪状态（OBSVMB）；5B 参与解算卫星（BESTSATA）；5C RTK 状态（RTKSTATUSA）；6 质量评估；7 结论。
   - 北斗无 IMU/INS，不输出北云 INS 专属章节；这属于产品能力差异，不是逻辑缺失。
9. **性能汇总表**
   - 北斗无 INS，速度 RMS 标为 N/A，而不是填 0；保持跨产品表格结构一致。
10. **图表**
    - 通用图与北云/华测保持同名与顺序；北斗额外增加 `obsvm_cno.png`、`obsvm_locktime.png`、`bestsat_count_ts.png`、`rtk_status_ts.png`。

## 手册字段映射实测验证
- `BESTNAVA`：34/34、54/54 全部解析成功；CRC/字段布局与手册一致。
- `OBSVMB`：
  - 二进制 CRC-32：33/33、54/54 全部通过。
  - `MessageLength` 与 `24B header + 4B obsNumber + N*40B + 4B CRC` 完全一致。
  - 通道跟踪状态解码后，BDS 信号类型能正确得到 B1I、B1C(Pilot)、B2a(Pilot)、B2b(I)、B3I；系统计数与 SATSINFO/BESTSAT 合理对应。
  - `psr_std/100`，`adr_std/10000`，`C/N0/100`。
- `SATSINFOA`：33/33、54/54 epoch 解析成功；PRN、方位角、高度角、系统、SNR 与 OBSVM/GSV 量级一致。
- `BESTSATA`：33/33、54/54 epoch 解析成功。
- `RTKSTATUSA`：字段偏移已修正为 `[11]pos type, [12]calc status, [13]ion detected, [15]ADR number`；实测 `pos_type=NARROW_INT`、`calc_status=5`、`ADR=100`。
- NMEA / ASCII CRC：本轮实测 0 校验错误。

## 修复记录（本轮检查中发现并已修复）
1. `chart_obsvm_locktime` 原先每颗星各自减去自身首个历元，导致所有曲线都从 0 开始，无法看出谁先失锁；已改为统一减去全局首个历元。
2. `performance_summary` 中无 INS 时速度 RMS 显示 0；已改为 N/A，避免把不可测项当作实测 0。
3. `check_message_integrity` 原先只统计 ASCII/NMEA；已将 OBSVMB 帧计入总帧数，其 CRC 仍在 `parse_obsvm` 中逐帧校验。
4. `GGA/GSA/GSV` 解析对空字段不够健壮：第二文件开头无解时出现空坐标、空 DOP、空 PRN；已改为保留 no-solution 记录或静默跳过空卫星槽，不再刷异常。
5. Matplotlib 3.9+ 中 `boxplot(labels=...)` 已弃用；已改为优先 `tick_labels` 并兼容旧版。
6. `EXPECTED_INTERVALS` 中 `BESTNAVA` 标称从 0.1s 修正为 1.0s，以本数据集实测为准，并在报告中说明。
